# 项目结构整理方案

## Context

CLAUDE.md 中的 `## 项目架构` 与实际项目结构存在以下问题：
1. `scripts/` 下混有入口脚本和 debug 脚本，与 `tests/` 下的 pytest 测试文件职责不清
2. `src/storage/` 与根目录 `storage/` 命名冲突（Python 中可共存，但需在 CLAUDE.md 中澄清）
3. 后续将爬取角色、剧情、装备等多种数据，需按数据类型模块化管理

用户决策：
- debug 脚本 → 移至 `scripts/debug/`
- `src/storage/` 保持不变

---

## 方案：按数据类型 + 脚本类型分区

### 目录职责定义

```
get_genshin_wiki/
├── src/                          # 可复用模块（库）
│   ├── crawler/                  # 通用爬虫客户端（与数据类型无关）
│   │   └── client.py            # MediaWikiClient
│   ├── parser/                  # 解析器（按数据类型分）
│   │   ├── book_parser.py       # 书籍解析器
│   │   └── character_parser.py  # 角色解析器（未来）
│   ├── storage/                 # 存储模块（Python 包，与根目录 storage/ 数据目录同名但机制不同）
│   │   └── writer.py            # 数据写入（BookStorage）
│   └── utils/                   # 通用工具
│
├── scripts/                      # 入口脚本（供人工执行）
│   ├── crawl_books.py           # 爬取书籍入口
│   ├── crawl_characters.py      # 爬取角色入口（未来）
│   └── debug/                   # 调试脚本（不常使用）
│       ├── test_book_list.py
│       ├── test_single_book.py
│       ├── save_book_html.py
│       └── save_book_list.py
│
├── tests/                        # pytest 测试（自动化）
│   ├── test_book_parser.py      # 书籍解析器单元测试
│   └── output/                  # 测试输出临时文件
│
├── storage/                      # 爬取数据存储（根目录）
│   └── book/
│       ├── books.jsonl
│       └── cleaned/
│
├── configs/                     # 配置文件
│   └── config.yaml
│
└── doc/                         # 文档
    ├── plan/
    └── operation_guide/
```

### 功能分区规则

| 路径 | 包含内容 | 说明 |
|------|---------|------|
| `src/` | 可复用模块 | crawler、parser、storage、utils |
| `scripts/` | 人工执行入口 | crawl_xxx.py，按数据类型分 |
| `scripts/debug/` | 调试脚本 | test_xxx.py、save_xxx.py，不常使用 |
| `tests/` | pytest 测试 | test_xxx_parser.py，只包含自动化测试 |

### 存储冲突说明

- `src/storage/` 是 Python 包（代码）
- `storage/` 是数据目录（数据）

Python 项目中 `src/` 下的包名与根目录数据目录可以同名，不冲突，因为它们处于不同的命名空间（包导入 vs 文件系统路径）。

## 实施步骤

### 步骤 1：创建 scripts/debug/ 目录并移动文件

需移动的文件：
- `scripts/test_book_list.py` → `scripts/debug/test_book_list.py`
- `scripts/test_single_book.py` → `scripts/debug/test_single_book.py`
- `scripts/test_single_book_save.py` → `scripts/debug/test_single_book_save.py`
- `scripts/save_book_html.py` → `scripts/debug/save_book_html.py`
- `scripts/save_book_list.py` → `scripts/debug/save_book_list.py`

保留的文件（入口脚本）：
- `scripts/crawl_books.py`（留在 scripts/）

### 步骤 2：更新 import 路径

移动后，debug 脚本中的 `sys.path.insert(0, ...)` 路径可能需要调整。实际验证后发现路径恰好兼容，无需修改。

### 步骤 3：修订 CLAUDE.md

更新 `## 项目架构`，写入：
- 各路径功能说明
- `src/storage/` 与 `storage/` 命名冲突说明（解释 Python 包与数据目录的区别）
- scripts/ 与 tests/ 的职责区分

### 步骤 4：更新相关文档

- `doc/operation_guide/2026-03-27_书籍爬取操作指南.md` — 更新 scripts/debug/ 路径引用
- `doc/plan/2026-03-27_书籍爬取方案_v2.md` — 更新文件索引

## 验证方法

1. 检查 `scripts/` 下只有入口脚本（`crawl_*.py`）
2. 检查 `scripts/debug/` 包含所有 debug 脚本
3. 检查 `tests/` 下只有 pytest 测试文件
4. 运行 `pytest tests/test_book_parser.py` 确保测试通过
5. 运行 `python scripts/crawl_books.py` 确保入口脚本可运行
6. 检查 CLAUDE.md 架构说明与实际结构一致
