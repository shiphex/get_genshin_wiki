## 1. 环境准备

### 1.1 进入虚拟环境

```bash
# Windows
.get_wiki\Scripts\activate

# Linux/Mac
source .get_wiki/Scripts/activate
```

### 1.2 安装依赖

```bash
uv pip install -e ".[dev]"
```

### 1.3 配置文件

主要配置文件位于 `configs/config.yaml`：

```yaml
mediawiki:
  api_url: "https://wiki.biligame.com/ys/api.php"
  base_url: "https://wiki.biligame.com/ys/"
  request_interval: 3
  timeout: 30
  max_retries: 3
  user_agent: "get_wiki_genshin/0.1.0 (...)"

storage:
  output_dir: "storage"
  artifacts_dir: "storage/artifacts"
  artifact_dir: "storage/artifacts"  # 兼容旧路径
```

## 2. 执行命令

### 2.1 完整爬取（推荐）

爬取所有圣遗物数据，包含断点续爬功能（已爬取的圣遗物不会重复爬取）：

```bash
python scripts/crawl_artifacts.py
```

**输出**：
- `storage/artifacts/structured/artifacts.jsonl` — 结构化圣遗物数据（JSONL 格式，每行一条）
- `storage/artifacts/raw/` — 原始 HTML（预留）
- `storage/artifacts/failed/failed_artifacts.txt` — 爬取失败的圣遗物记录
- `storage/artifacts/manifests/<run_id>.json` — 运行摘要
- `storage/artifacts/alerts/<run_id>.json` — 告警记录

### 2.2 测试圣遗物列表提取

仅提取圣遗物列表，不爬取详情页：

```bash
python scripts/debug/save_artifacts_list.py
```

### 2.3 测试单件圣遗物爬取

爬取指定圣遗物的详情页并保存测试结果：

```bash
python scripts/debug/save_artifacts_html.py
```

## 3. 输出文件说明

### 3.1 artifacts.jsonl 结构

每行一条 JSON 记录，字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | string | 圣遗物套装名称 |
| `url` | string | 圣遗物页面 URL |
| `fetched_at` | string | 爬取时间（ISO 格式） |
| `info.套装名称` | string | 圣遗物套装名称 |
| `info.稀有度` | string | 如"5星" |
| `info.TAG` | string | 圣遗物 TAG |
| `info.实装版本` | string | 实装版本 |
| `info.两件套效果` | string | 2件套效果 |
| `info.四件套效果` | string | 4件套效果 |
| `info.部件列表` | list | 各部件信息数组 |
| `info.部件列表[].名称` | string | 部件名称（如"铭记之花"） |
| `info.部件列表[].类型` | string | 部件类型（如"生之花"） |
| `info.部件列表[].描述` | string | 部件描述 |
| `info.部件列表[].故事` | string | 部件故事文本 |
| `info.获取途径` | list | 获取途径数组 |
| `info.获取途径[].类型` | string | 途径类型（"副本"或"NPC"） |
| `info.获取途径[].副本类型` | string | 副本类型（如"祝圣秘境"） |
| `info.获取途径[].副本名称` | string | 副本名称 |
| `info.获取途径[].副本等级` | string | 副本等级（如"Ⅰ~Ⅴ"） |
| `info.获取途径[].星级` | string | 星级 |
| `info.获取途径[].NPC姓名` | string | NPC姓名 |
| `info.获取途径[].获取方式` | string | 获取方式 |
| `info.获取途径[].详细描述` | string | 详细描述 |

### 3.2 存储目录布局

```
storage/artifacts/
├── raw/                    # 原始 HTML（预留）
├── cleaned/                # 预留
├── structured/              # 结构化 JSONL 数据
│   └── artifacts.jsonl
├── failed/                  # 失败记录
│   └── failed_artifacts.txt
├── manifests/               # 运行摘要
│   └── <run_id>.json
└── alerts/                 # 告警记录
    └── <run_id>.json
```

## 4. 告警与日志

### 4.1 告警规则

爬取过程中可能触发以下告警：

| 告警类型 | 说明 |
|----------|------|
| `empty_list_page` | 列表页抓取数量为 0 |
| `invalid_artifact_piece_count` | 圣遗物部件数不足 5 |
| `writer_failure` | 数据写入失败 |

### 4.2 查看告警

告警文件位于 `storage/artifacts/alerts/<run_id>.json`，包含告警等级、消息和详情。

### 4.3 运行摘要

运行摘要位于 `storage/artifacts/manifests/<run_id>.json`，包含：
- `run_id`、`namespace`、`started_at`、`finished_at`
- `fetched_count`、`saved_count`、`failed_count`、`warning_count`
- `config_snapshot`

## 5. 常见问题处理

### 5.1 爬取失败

检查 `storage/artifacts/failed/failed_artifacts.txt`，失败记录格式为：`圣遗物名\t失败原因`

重新爬取失败圣遗物：删除 `failed_artifacts.txt` 中的对应行，或清空文件后重新运行 `python scripts/crawl_artifacts.py`

### 5.2 请求超时

默认超时 30 秒，最大重试 3 次，使用指数退避策略。若持续超时，可能是网络问题或 Wiki 服务器限速，建议等待后重试。

### 5.3 数据不完整

如果某圣遗物缺少字段，可能是页面 HTML 结构变化。检查 `scripts/debug/save_artifacts_html.py` 输出，或查看 `tests/output/` 下的临时文件进行调试。

### 5.4 清理数据

删除所有已爬取数据（慎用）：

```bash
rm storage/artifacts/structured/artifacts.jsonl
rm storage/artifacts/failed/failed_artifacts.txt
rm storage/artifacts/manifests/*.json
rm storage/artifacts/alerts/*.json
```
