> 本文档版本：v1.0（2026-03-29）

## 1. 环境准备

### 1.1 进入虚拟环境

```bash
# Windows
.get_wiki\Scripts\activate

# Linux/Mac
source .get_wiki/Scripts/activate
```

### 1.2 安装依赖

```bash
uv pip install -e ".[dev]"
```

### 1.3 配置文件

主要配置文件位于 `configs/config.yaml`：

```yaml
mediawiki:
  api_url: "https://wiki.biligame.com/ys/api.php"  # MediaWiki API 地址
  base_url: "https://wiki.biligame.com/ys/"         # Wiki 基础地址
  request_interval: 3                                # 请求间隔（秒）
  timeout: 30                                        # 请求超时（秒）
  max_retries: 3                                      # 最大重试次数
  user_agent: "get_wiki_genshin/0.1.0 (...)"

storage:
  output_dir: "storage"
  arm_dir: "storage/arm"                             # 武器数据输出目录
```

## 2. 执行命令

### 2.1 完整爬取（推荐）

爬取所有武器数据，包含断点续爬功能（已爬取的武器不会重复爬取）：

```bash
python scripts/crawl_arms.py
```

**输出**：
- `storage/arm/arms.jsonl` — 结构化武器数据（JSONL 格式，每行一条）
- `storage/arm/arms.json` — 结构化武器数据（JSON 格式，可读）
- `storage/arm/failed_arms.txt` — 爬取失败的武器记录

### 2.2 测试武器列表提取

仅提取武器列表，不爬取详情页：

```bash
python scripts/debug/test_arms_list.py
```

### 2.3 测试单件武器爬取

爬取指定武器的详情页并保存测试结果：

```bash
python scripts/debug/test_single_arm_save.py
```

默认测试武器：狼的武功歌

## 3. 输出文件说明

### 3.1 arms.jsonl 结构

每行一条 JSON 记录，字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | string | 武器名称 |
| `url` | string | 武器页面 URL |
| `fetched_at` | string | 爬取时间（ISO 格式） |
| `info.名称` | string | 武器名称 |
| `info.稀有度` | string | 如"5星" |
| `info.性能描述文本` | string | 攻击力 46-608 /// 暴击率 7.2%-33.1% |
| `info.武器技能` | string | 武器技能名称 |
| `info.武器技能文本描述` | string | 技能详细描述 |
| `info.武器介绍` | string | 武器介绍 |
| `info.实装版本` | string | 实装版本 |
| `info.获取途径` | string | 获取途径 |
| `info.武器类型` | string | 武器类型 |
| `info.武器TAG` | string | 武器TAG |
| `info.突破材料` | list | 突破材料列表 |
| `info.故事` | string | 故事文本（`<br />` 换行处理） |

### 3.2 arms.json 结构

与 `arms.jsonl` 相同内容，但以 JSON 数组格式存储，便于阅读和调试。

## 4. 常见问题处理

### 4.1 爬取失败

检查 `storage/arm/failed_arms.txt`，失败记录格式为：`武器名\t失败原因`

重新爬取失败武器：删除 `failed_arms.txt` 中的对应行，或清空文件后重新运行 `crawl_arms.py`

### 4.2 请求超时

默认超时 30 秒，最大重试 3 次，使用指数退避策略。若持续超时，可能是网络问题或 Wiki 服务器限速，建议等待后重试。

### 4.3 数据不完整

如果某武器缺少字段，可能是页面 HTML 结构变化。检查 `scripts/debug/test_single_arm_save.py` 输出，或查看 `tests/output/` 下的临时文件进行调试。

### 4.4 清理数据

删除所有已爬取数据（慎用）：

```bash
rm storage/arm/arms.jsonl
rm storage/arm/arms.json
rm storage/arm/failed_arms.txt
```
