# v2.3 折叠剧情完整性修复计划

用户需求：使用 `genshin_wiki_data_20260605.zip` 替换本地 data 基础，在
`develop/v2.3` 修复通用折叠剧情解析，保持现有业务字段和原始数据。

## 调查结论与实现选择

- 0605 旧产物《尾声的尾声》有 117 个对话条目。旧
  `_extract_archon_dialogues` 路径只展开选项模板，随后 `strip_code()`
  删除整个折叠模板。普通 `*说话者：内容` 行不在模板内，因此保留。
- 当前 v2.2 已经将任务对话接入 `recovery/extract.py` 和 `recovery/legacy.py`，
  折叠内容可以递归读取；直接重解析原页有 157 个条目，夺心过场已有 17 行。
  本次沿用这一架构，不重新启用旧提取器。
- 现有恢复层只在 Text 节点的源码换行处分行；同一行的 `<br>` 多角色对话会合并。
  在对话上下文中按 AST 的顶层 br 划分候选片段，再独立识别说话者；
  无标记片段保留为旁白并诊断，不继承说话者。内联显示节点和明确指定说话者的
  人物对话模板保留其内容范围内的换行。
- 业务投影会删除有子场景的章节前导场景，即使前导场景有对白；仅删除空包装场景。
- 剧情范围以外的普通折叠内容保留为 description 并诊断，不猜测其为角色台词。
- 保留现有黑幕显示规则（例如原文 `温迪——！{{黑幕|哑巴开口}}` 的显示内容），
  不在本修复中擅自删改编辑注释或重新定义其含义。
