# 非剧情实体解析抽样调查（2026-10-31）

结论：存在解析不完整和不需要的内容混入，当前代码可复现 7 类问题。除此之外，武器数值、圣遗物套装效果、料理效果等缺失属于当前持久化模型的覆盖范围限制，不能与解析器遗漏混为一谈。

## 调查方法与边界

- 逐页比较：0605 ZIP 的原始 payload → 本地原始 payload → 现存业务 JSON → 当前解析器重新生成的业务 JSON。角色重跑读取本地配套语音页，沿用正式入口的行为。

- 当前重跑环境：Python 3.11.7、mwparserfromhell 0.7.2。代码哈希见 `summary.json`。
- 补充机械扫描上述 10 个业务目录共 **3,307 个 JSON**，检查空字段、注释和 Wiki 标记。扫描数量不是语义审计数量。
- 调查期间核对过的 3,558 个输入文件，在脚本结束时重新核验哈希未变；该数字包含业务目录扫描、所读原始页和依赖页，不代表全库原始数据哈希核验。

## 已确认的问题

以下“现存”指 `data/parsed`，而“重跑”指本报告目录的 `current/`。F1—F7 均在当前代码下复现，不只是旧文件问题。机器证据见 [findings.json](non_story_sample_audit_2026-10-31/findings.json)，其中 `raw_line` 是 **payload 内 Wikitext 的行号**，不是外层 JSON 的行号；同时保存精确字符区间和原文。

### F1：角色信息子模板未合并，已有输出字段为空

七七原始 `角色/信息` 明确包含：

```text
|归属=不卜庐
|职业=不卜庐采药人
```

现存和重跑的 `角色.归属`、`角色.职业` 均为 `""`。钟离、芙宁娜、玛薇卡、丝柯克同样丢失子模板信息；丝柯克的 `衣装名称=碎星` 也没有进入输出。

根因：`parse_character_page` 只通过 `_select_best_template` 选择一个主模板作为 `attributes`，随后从它读取职业、归属、昵称和衣装；没有合并 `角色/信息`。这不是 schema 不支持：持久化结构已经有这些字段。

隔离验证：直接对七七的 `角色/信息` 调用既有字段提取助手，可以取得“不卜庐采药人”。问题在字段来源选择。

影响范围线索：现有 126 个角色 JSON 的“归属”“职业”“昵称/外号”均为空。这里只对上述 5 个常规角色页确认“原文有值却输出空”；不能把 126 个空值全部认定为缺陷。

定位：[parser.py](../../get_genshin_wiki/parser.py)，`parse_character_page`（756 行起）、`_select_best_template`（4409 行起）。

### F2：空编号别名覆盖非空冒险笔记，整篇内容消失

七七与钟离的 `角色/故事` 同时含有：

```text
|冒险笔记名称=水产品
|冒险笔记=魔神战争期间，提瓦特大陆上每一处都燃烧着战火。……
|冒险笔记1=
```

钟离的《水产品》、七七的《不死之身的居家旅行实用宝典》，现存和重跑均输出 `冒险笔记: {}`。

根因：`_extract_adventure_notes` 将无编号的 `冒险笔记` 和带编号的 `冒险笔记1` 都映射到键 `"1"`，后遇到的空值覆盖了正文。

隔离验证：仅在内存副本中删除空 `冒险笔记1`，既有提取函数即恢复七七的完整笔记。芙宁娜、玛薇卡、丝柯克的无此空别名样本能保留笔记，构成对照。

定位：`parser.py::_extract_adventure_notes`（5226 行起）。

### F3：道具的显示模板被当作无用标记，删掉操作条件

| 页面 | 原始有效内容 | 现存及重跑 |
|---|---|---|
| 参量质变仪 | `需要进行{{颜色\|蓝\|元素攻击}}使其能量达到……` | `需要进行使其能量达到……`，缺少“元素攻击” |
| 浓缩树脂 | 红色备注包含适用的树脂奖励范围、排除项，以及“持有上限为5个” | 整段备注消失，只留下获取副本奖励的一句话 |

根因：道具字段经过 `_resolve_value` → `_normalize_plain_text` → `strip_code()`，没有先展开 `颜色` 的可见正文。现有 `_clean_field_value` 使用的显示处理与它不同，导致同类文本在不同数据族中表现不一致。

隔离验证：`_normalize_plain_text('{{颜色|蓝|元素攻击}}')` 返回空字符串，而 `_clean_field_value` 对同一输入返回“元素攻击”。

这里仅核对快照中的文字是否保留，不对浓缩树脂快照中“三倍”等陈述的游戏事实正确性作判断。

定位：`parser.py::_normalize_plain_text`（4808 行起）、`_clean_field_value`（5430 行起）。

### F4：武器输出混入编辑者填写说明

「究极霸王超级魔剑」现存和重跑均有：

```text
类型 = 双手剑  <!--单手剑、双手剑、长柄武器、法器、弓 -->
```

“介绍”还保留 `<!--对武器的简要介绍，可在“角色”面板->“武器”标签查看 -->`。这些是 HTML 注释中的编辑提示，不应成为武器知识正文。

根因：武器的类型、介绍直接取模板原值；故事只替换部分换行标签，没有统一经过注释和显示标记清洗。

机械扫描发现现有 236 个武器 JSON 中 **50 个含 `<!--`**，4 个含 Wiki 链接或模板标记。这是扩查线索；本轮没有逐条判定另外 49 个文件的注释语义。

定位：`parser.py::parse_weapon_page`，889、906—907 行。

### F5：圣遗物获取方式只保留较短来源，且错误处理多个链接

- 昔日宗室之仪的详细 `获取方式` 包含秘境掉落、合成台、世界任务“靖世九柱”。但现存与重跑都只有 **“华池岩岫：岩牢”**，遗漏后两种渠道。
- 祭火之人的原文是 `[[爆炎树]]、[[无相之火]]、[[古岩龙蜥]]掉落`，输出却是 **`爆炎树：、[[无相之火]]、[[古岩龙蜥]]掉落`**，增加了错误冒号并保留部分链接标记。

根因：`_parse_artifact_obtaining_method` 优先处理简短的 `获取途径`，匹配到第一个 Wiki 链接后提前返回，不再读取更完整的 `获取方式`；同时默认第一个链接后应是冒号格式，不能正确处理链接并列列表。

隔离验证：仅在内存中移除昔日宗室之仪的简短 `获取途径` 字段，既有助手便能输出“合成台”和“靖世九柱”。

定位：`parser.py::_parse_artifact_obtaining_method`（4646 行起）。

### F6：材料用途依赖动态查询，既未得到完整关系，也未妥善隔离源码

清心、慕风蘑菇、「自由」的教导、北陆单手剑原胚，原始“用处”均含 `#ask/#arraymap`，用于动态生成角色、武器或料理关系。

| 页面 | 现存用途 | 当前重跑 |
|---|---|---|
| 清心 | `解锁珠钿舫任务、` | 保留这一段，同时混入 `{{#arraymap:{{#ask:分类:角色……` 等查询源码 |
| 慕风蘑菇 | `风之寻宝罗盘（锻造）、` | 同样混入未展开查询 |
| 「自由」的教导 | 合成与旅行者的静态条目 | 其余角色关系仍未展开，查询源码混入 |
| 北陆单手剑原胚 | 央陆、垠土原胚的异梦转化 | 动态锻造武器列表未展开，查询源码混入 |

独立核对：甘雨原始页的 `角色/突破简` 明确设置“突破特产材料=清心”，但清心 JSON 的用途没有甘雨。这说明不是材料没有其他用途。

根因：当前材料解析不执行语义查询，也不从本地其他实体建立这些关系。现存 JSON 删除了查询部分；当前复杂原文提取与纯文本转换组合则把部分未展开查询作为文字留下。两种结果都不等于完整的用途数据。

分类：**动态依赖未解析 + 输出源码污染**。不能只靠删除花括号解决，也不能凭空补出查询结果。需要明确处理本地可证实的关系，以及无法解析的依赖状态。

定位：`parser.py::parse_material_page`（1466 行起）、`_extract_param_from_wikitext`（5054 行起）、`_normalize_plain_text`（4808 行起）。

### F7：技术页面和文档示例进入野生生物实体目录

`Widget:CardCanvas` 原始命名空间为 **274**，正文是组件脚本与演示模板，现存和重跑却将其作为 **“松鼠”** 输出到野生生物目录。

补充扫描 209 个野生生物 JSON，找到以下 4 个明确的技术/说明页记录：

| 原始页面 | 原始命名空间 | 现存输出名称 |
|---|---:|---|
| Widget:CardCanvas | 274 | 松鼠 |
| 数据组指南 | 0 | 填写的内容1 |
| 模板:野生生物图鉴 | 10 | 模板:野生生物图鉴 |
| 模板:野生生物图鉴/文档 | 10 | 金团雀 |

根因：存在图鉴模板或字段即被接受为实体，解析入口没有核对页面用途；批量解析对分类成员标题也缺少实体资格判断。只过滤非主命名空间还不足以处理“数据组指南”这样的主命名空间文档。

定位：`parser.py::parse_wildlife_page`（1292 行起）；`tools/reparse_and_store.py::_process_entity`（488 行起）。另外 3 页本轮检查现存产物与原始页身份，只有 Widget 页做了独立重跑。

## 数据模型本身未覆盖的有效内容

以下原文有值，但当前模型/正式持久化结构没有对应输出。它们构成业务知识覆盖限制，不能直接称作本轮发现的解析回归：

| 数据族 | 原文实例 | 当前范围限制 |
|---|---|---|
| 武器 | 天空之刃：初始攻击力46、90级攻击力608、技能“穿刺高天的利齿”及效果 | `WeaponRecord` 不输出稀有度、攻击力、副属性、被动技能 |
| 圣遗物 | 角斗士：两件套攻击力提高18%；四件套普攻伤害提高35% | `ArtifactSetRecord` 只输出获取方式及部件名称、描述、故事 |
| 食物 | 甜甜花酿鸡：普通/完美/失败料理的恢复数值 | `FoodRecord` 输出三种介绍，不输出对应效果说明 |
| 怪物 | 遗迹守卫：物抗70%、火抗10%，以及技能说明 | `MonsterRecord` 不输出抗性、战斗技能等 |
| 角色 | 天赋、命座、属性与突破数据 | `CharacterRecord.to_storage_dict()` 采用精简人物/故事结构，未持久化这些战斗信息 |

这些限制也说明：当前 `parsed` 适合的知识用途受 schema 约束，不能仅凭“原始页面已抓取”推断其已涵盖完整游戏知识。原木刀“获取途径”简化为“图纸兑换”同样是现有文档明确规定的有损摘要，未另记为代码缺陷。

- 铁蜂刺锻造材料、渔获的“赤穗酒枡”、璀璨原钻碎屑的旅行者突破用途能够正确保留。
- 丘丘人的三种面具、遗迹守卫的混沌系列、若陀龙王的三种专属素材，在检查的掉落字段中符合原文；摩拉等通用项是现有代码明确过滤的对象。

- 旅行者属于聚合/入口性质的边界样本，多数字段为空；需结合角色变体页及转引规则确定预期，未把它所有空字段算作 F1。

## 现存数据与当前代码不一致

**38 页中，26 页重跑与现存 JSON 完全一致，12 页不同**。38 份现存 JSON 均仍与 ZIP 中旧解析结果一致。

- 角色 5 页：七七、芙宁娜、旅行者、玛薇卡、丝柯克。差异涉及介绍/人物/故事的显示文本；例如七七旧“贰·故事”有“因为是，所以……”这样的缺词，当前重跑恢复了部分显示文字。
- 材料 4 页：慕风蘑菇、清心、「自由」的教导、北陆单手剑原胚，差异包含 F6 的查询源码混入。
- 道具 3 页：浓缩树脂、「四方八方之网」、参量质变仪，差异涉及介绍或列表标记；F3 的关键条件丢失仍存在。

这 12 页并不全是“重跑后变好”。只重新生成数据不能视为完整性修复；应先修复并验证规则，再更新相关业务产物。完整字段差异路径见 [summary.json](non_story_sample_audit_2026-10-31/summary.json)。

## 建议的处理顺序

1. 先修已有 schema 内的确定缺陷：F1 子模板字段来源、F2 空值覆盖、F3 显示模板正文丢失。
2. 统一各数据族的输出清洗，移除 F4 编辑注释，并修正 F5 多来源合并和链接列表处理。
3. 增加 F7 的页面身份检查，整理误进入实体目录的记录。
4. 为 F6 设计可追踪的依赖解析：本地能证实的关系可建立索引，不能解析的查询保留诊断，避免静默删掉或混入知识正文。
5. 单独讨论需要扩展的战斗/效果字段；这是数据契约变更，不应与修补已有字段混在一起。
