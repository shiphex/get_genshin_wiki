# 第二轮文档/UI 误分类补修（2026-11-04）

已修复第二轮反馈中 11 条文字的类型与说话者错误，并补修同页“书柜上的纸张”这一处同类误判。文字、阅读标签、原顺序、任务流程与来源均保留；祈月笺的 5 条署名/提示继续单独保存为 annotation。

最终全套测试：**209 passed / 18 subtests passed**。这支持已检查范围的修复结论，不代表全库剧情语义验收通过。

## 根因与规则

之前的文档判断只检查折叠标题。“可进入千织屋”和“额外对话”仍继承对白语境；随后任何非空冒号前缀都可能被当作人物，导致“阅读”“查看「祈月笺」”“本子上的备忘录”及“「附言”获得角色身份。

共享恢复层现在增加行级判断：

- 明确阅读动作（阅读、查阅、翻阅、查看及带书名/引号对象的形式）保留为旁白。
- 文档物件标签（笔记、备忘录、信件、便条、纸张等，支持桌上/书柜上等位置前缀）保留为旁白。
- 冒号在配对引用内、而非在已闭合的角色名后时，保留整句引用为旁白。
- 分类只影响当前行。同折叠、同选项分支中的真实发言继续识别，不把混合折叠整体改成文档。
- 文档的注释分离只检查冒号后的正文。完整黑幕正文继续保留并诊断歧义，不能因“阅读：”标签可见而把正文拆成注释。
- 不完整说话者引号，例如原文 `「公子：解散！`，保留发言与原始姓名拼写，标记 `speaker_status=unresolved` 并产生 `unbalanced_speaker_quote` 诊断，不将其直接改成文档。

恢复单元新增可选的 `classification_reason`，解释阅读动作、文档物件或配对引用的分类依据。业务四字段 Schema 未变，三个任务适配器共用该规则。没有按页面标题、祈月笺名称或具体台词写特例。
