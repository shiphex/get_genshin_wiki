[独立抽样报告、原始哈希和复核脚本](fold_dialogue_sample_audit_2026-10-30.md)。

## 四项缺陷与修复

| 审计项 | 根因 | 修复后的行为 |
| --- | --- | --- |
| F1 后续剧情缺失 | 标题只识别固定名称；关闭主剧情后，后续正文未提取，折叠又被视为 description | 识别中文前缀加剧情/对话的标题，按层级保留父剧情区；《荷叶与森林的答案》新增 55 条台词、7 个选项标签 |
| F2 黑幕污染台词 | 将显示模板参数直接拼进正文；仅给整行标来源性质，业务投影没有区分提示与原句 | 有可见原句的附着黑幕分离为 annotation，主对白排除其原始范围；原文、位置、场景、分支仍保留 |
| F3 账目当角色 | 文档折叠继承 dialogue，任何冒号都被当作角色分隔符 | 明细、账目、日志、留言、档案等文档语境按旁白保留全文，六条账目不再成为动物角色发言 |
| F4 空后缀静默丢文 | 将长叙述拆成 speaker 和空 content，空渲染直接返回 | 冒号后为空时保留整行为旁白，并记录 `empty_speech_after_colon` |

不是给单页标题或台词补硬编码：生产代码按标题结构、折叠文档语境、明确 Wiki 标记与
原文边界处理。泛化标题时同时修正了层级：`与温迪对话` 子流程不能重新设置剧情根层级，
否则会误关后面的同级流程。非剧情的同级标题仍关闭剧情区。

修复示例：

```text
旅行者：温迪——！{{黑幕|哑巴开口}}
```

业务 JSON：

```json
{"说话者":"旅行者","内容":"温迪——！","类型":"traveler","所属任务流程":"将天空之琴交给芭芭拉"}
```

`哑巴开口` 在独立 annotation 中保留，而不是删除原始文字或继续并入台词。
`十一号盗宝鼬：大郎，6岁。` 的业务条目则为 `说话者=""`、`类型="narration"`，内容保留整行。

## 黑幕边界与恢复契约

没有把所有黑幕一律删除或一律认定为 Wiki 注释：

- 台词中另有可见内容时，附着黑幕单独保存；可见内容也可以是摩斯码或标点发言。
- 只有黑幕的发言仍保留，产生 `ambiguous_blackout_content`，不猜测是否为完整原句。
- 书籍、故事等非对白隐藏正文沿用显示规则，不套用台词附注剥离。
- 说话者前明确的编者补全请求单独保存；儿童等角色限定词保留并标为 unresolved。
- 冒号对白与人物对话模板的显式角色参数共用处理，不让后者绕过相同规则。

`recovery/display.py` 增加原文可见路径的黑幕节点定位、精确范围排除及重放；
`recovery/extract.py` 增加上下文分类、注释分离和共享说话者处理。
legacy adapter 使用已有业务字段，不把 annotation 投影成角色台词或选项。

恢复 API 增加 `annotation` 类型与可选 `excluded_spans`、`speaker_excluded_spans`；
注释记录 `annotation_status=unresolved` 保留分类不确定性。单元的完整 source 范围可以
包含另行保存的标记，主台词的 text_spans 不包含被分离文字；使用 `replay_unit()` 重放。
直接消费权威 JSONL 的程序需支持这些新增信息，业务四字段的消费者无需迁移 Schema。

注释候选与明确诊断均可追溯到原始页，不代表已经逐条确认它们都是游戏外提示。
将已分离文字重新作为游戏原句使用之前，仍应复核来源与语义。
